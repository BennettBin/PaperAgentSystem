# Paper Discovery

## 目标

根据用户给出的研究主题，从 Crossref、Semantic Scholar、OpenAlex 和 arXiv 发现候选论文。该 Skill 返回的是外部学术元数据，不把标题或摘要冒充为已读取、已核验的论文正文证据。

## Execution Steps

1. 从用户问题中保留主题、专业术语、模型名和必要的限定词，不自行扩大研究问题。
2. 四个只读 Tool 可以并行执行；单个数据源超时、限流或不可用时，保留其余来源的结果并报告失败来源。
   - `search_crossref`：正式出版物与 DOI 元数据。
   - `search_semantic_scholar`：语义检索、摘要与引用元数据。
   - `search_openalex`：开放学术图谱与开放获取元数据。
   - `search_arxiv`：预印本元数据。
3. 每个来源默认最多取 5 条，调用参数上限为 20 条，避免无界响应和不必要的第三方 API 压力。
4. 合并时优先按规范化 DOI 去重；缺少 DOI 时按大小写和标点归一化后的标题去重。
5. 同一论文命中多个来源时合并来源标识，优先保留 DOI、开放获取地址、摘要、作者和引用次数等更完整字段。
6. 输出必须含标题、年份（若有）、作者（若有）、来源、DOI/链接（若有），并明确提示用户：如需基于正文问答，应继续上传或导入论文 PDF。

## Structured Input

格式为 `object`，必须包含请求、文件列表、会话 ID 和参数对象；外部论文发现允许 `file_ids` 为空。

## Structured Output

格式为 `markdown`，必须包含 `## 论文检索结果`，并明确元数据来源、去重规则和不可用来源。

## Acceptance

- 每个 Tool 的输入输出均通过真实 Pydantic Schema 校验。
- 去重后的结果保留可访问链接和至少一个元数据来源。
- 单个来源失败不影响其他成功来源；四个来源全部失败时返回统一可重试错误。
- 外部元数据不进入 PDF 证据 ID 或正文引用链。

## Anti-Patterns

- 不用于检索已上传 PDF 内部的段落；该场景使用 `search_document`。
- 不根据元数据摘要生成需要正文证据支撑的实验结论。
- 不绕过 Tool Runtime 的权限、白名单、超时、幂等和输出大小限制。
